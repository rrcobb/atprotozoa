built-by-bot — policy & limits

The one label

built-by-bot — severity inform, blurs nothing, default setting ignore. It is a descriptive badge, not a content warning. Subscribing to it should never hide anything from you; at most it adds a small marker.

What gets labeled

  • The @buildthis.bisks.net account.
  • Every post that requested a site the bot went on to ship, taken from the bot's own public event log. These are the same URIs in its public /shipped feed.

What does not get labeled

Anything this project didn't make. No account is assessed for "botness." The wider idea — labeling automated accounts across the network — was considered and rejected: it requires judging strangers, it would be wrong often, and a wrong label sits on someone else's post where they didn't ask for it.

The one place this touches a third party

A tagging post is authored by the person who asked for the site, not by the bot. Labeling it asserts "a bot built what this post asked for" — true, and about the site rather than the author. It's public information already. If that still reads as one step too far, the fallback is labeling only the bot account, which is a one-branch change in subjectsToLabel. Ask and it's done.

Getting a label removed

Ask — reply to @buildthis.bisks.net or @bisks.net — and the post comes out of the set. There's no review board and no appeal process to navigate; the whole subject list is derived from a public log, and removal is a code change, applied on request, no reason needed.

Ways this is not a complete labeler

  • No label stream. A canonical labeler serves com.atproto.label.subscribeLabels over a long-lived websocket. This runs on a stateless Cloudflare Worker with no standing connections (a deliberate repo-wide constraint), so it serves queryLabels only. Clients that query see every label; consumers that only ingest the stream see nothing. The subscribe endpoint answers and closes cleanly rather than hanging, so a subscriber finds out immediately instead of timing out.
  • No moderation reports. It declares no report reason types and accepts no reports. It emits one descriptive label and does nothing else.
  • No negations. Nothing it labels ever stops being bot-built, so there is no retraction path; removal happens by dropping the subject, not by publishing a neg label.
  • Backfill is bounded. The upstream event log pages at 500 entries with no cursor, so if the log is longer, the earliest ships aren't labeled. The front page says so when it's happening, rather than quietly labeling a prefix.

Signatures

Labels are signed for real, P-256 / ES256, over the dag-cbor encoding of the label without its signature field, normalized to the low-S form atproto requires. The public half lives in the labeler account's DID document as #atproto_label, so anyone can verify a label came from this service.
