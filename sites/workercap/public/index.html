explainer · infra

799 Workers,
500 allowed.

This repo hosts 803 small sites. Cloudflare lets one account hold 500 Workers. Seven steps cover the setup before, the wall, the fix, and the setup after.

Step 1 · the limit

One account holds 500 Workers.

A Worker is one deployed script on Cloudflare. The Workers Paid plan caps an account at 500 of them. Cloudflare counts a Worker that serves static files the same as one that runs code.

Step 2 · before

Every site got its own Worker.

Each folder under sites/ had a wrangler.toml. Each deploy made a Worker named atprotozoa-<site>. Each Worker took a route for its hostname and handed the request to a bundle of static files.

Most of those Workers held the same ten lines: pass the request to the file bundle. 592 sites needed nothing more.

Step 3 · the wall

The account reached 799.

Past 500, existing Workers keep serving and redeploying. Creating a new Worker fails:

You have exceeded the limit of 500 Workers
on your account. [code: 10037]
  1. 2026-08-20 — the account passes 500. Deploys keep working, because newer wrangler creates scripts through an upload path that skips the check.
  2. 2026-09-17 — a limit-increase request goes to Cloudflare. No answer arrives. Cloudflare points accounts that want more than 500 to Workers for Platforms.
  3. 2026-10-29 — strandbeest becomes the last new Worker.
  4. 2026-10-31 — the upload path starts returning 10037. Nine new sites wait undeployed.
Step 4 · the idea

Most Workers did the same job, so one Worker takes that job.

The fallback Worker already held the wildcard route *.bisks.net/*. It reads the hostname, picks the matching folder, and serves the files. A site with no server code needs a folder and no Worker.

Each hosted site keeps its own hostname, so it keeps its own origin, cookies, localStorage and OAuth login.

Step 5 · the move

Four moves per site, checked at each one.

  1. classify — migrate-to-host.mjs picks sites whose Worker does nothing but pass requests to the file bundle. A site with a binding, a cron, or real code stays put.
  2. host — delete the site's wrangler.toml and src/, list it in fallback/sites.json, push. Fallback deploys with the site inside.
  3. cut over — cf-cutover.mjs --routes removes the old route, waits for fallback to answer, and compares the status and a hash of /. A mismatch puts the route back.
  4. delete — cf-cutover.mjs --workers deletes the old Worker. This frees the slot. Workers that hold a Custom Domain go one at a time, since deletion takes the DNS record with it.

Four host Workers (atprotozoa-host-1 to -4, 148 sites each) are in place to split the hosted sites into groups, so a push to one site redeploys its group of 148 and leaves the other 444 alone.

Step 7 · the other limits

The Worker count has two neighbors.

The same zone has two more ceilings. Each one broke a deploy before the Worker cap did.

A new site today is a folder with public/ and site.json. It takes zero Worker slots and zero routes, since the wildcard route covers it. A site that needs server code takes one slot and one route.
