how the numbers are real (and why they're frozen)

While it ran, every site that carried the footfall beacon reported one visit on load and one dwell time (milliseconds on page, capped at 30 minutes) when the tab closes or hides. Both landed in a Durable Object here — no client could inflate its own numbers, since the count only moved when this Worker recorded it.

That beacon was retired on 2026-08-13: writing every visit to a shared Durable Object didn't fit the constellation's frontend-first, Cloudflare-cheap house rules, so the ingestion path was removed and add-beacon.mjs deleted. Nothing reports here anymore — no site, old or new, can be retrofitted onto this board, and the totals below are a snapshot, not a running count. This page stays up only while its data-retention decision is pending.

Range only offers all-time: the Durable Object never stored per-visit timestamps, only a running total per site, so there's no hourly, daily, weekly, monthly, or yearly number to show — those options are visible rather than removed, so the gap is honest instead of silent. Worst first is real: it flips every sort to ascending, so the tabs still work as a "who's actually not getting visited" view.

The tab, search filter, and worst-first toggle all live in the URL, so a specific slice of the frozen board — "prompters by time, filtered to dave" — is a link you can actually share, not just a state you can describe. Export CSV downloads whatever's on screen, in that same filtered order, since a snapshot this static is worth keeping a copy of.

Prompter leaderboards sum the visits/time of every site built for that handle (the by field in each site's manifest). One prompter, many asks — this is the total footfall across everything they've had built.
